# Pilot test set

Ten projects with reference answers, plus ten holdout documents, and what this
pipeline extracted for the same documents. Use it to score an extraction
against a known answer.

## The files

| File | Rows | What it is |
|---|---|---|
| `reference_gold_general.csv` | 10 | The answers, project level, P001–P010 |
| `reference_gold_locations.csv` | 60 | The answers, location level |
| `reference_gold_results.csv` | 56 | Result values with their metric, unit and page |
| `reference_holdout_general.csv` | 10 | The answers for ten holdout documents, H001–H010 |
| `pipeline_gold_general.csv` | 10 | What this pipeline extracted, project level |
| `pipeline_gold_locations.csv` | 239 | What this pipeline extracted, location level |
| `pipeline_holdout_general.csv` | 10 | Pipeline output for the holdout |
| `documents.csv` | 20 | Which PDF each project code refers to |

The PDFs are in the Zotero group library under **Pilot test set (reference
answers)**, in two sub-collections, `Gold P001-P010` and `Holdout H001-H010`.
Filenames there match `documents.csv`.

## Gold and holdout are different on purpose

The **gold** projects are the ones the extraction prompts were developed on.
Scores on them are optimistic by construction.

The **holdout** documents were never used for tuning. They are the honest
measure of how the pipeline does on something it has not seen. Keep them that
way: if you tune against the holdout, there is nothing left to measure with.

## Reading the answer files

**Several answers can be correct.** A cell containing `||` lists alternatives,
any one of which counts as right:

```
project_lead   CON14 || NEPAD || African Union Development Agency
location_count 22 || 24 || 26
```

This is not "all of these apply". It is "any of these is an acceptable
answer". 86 cells in the gold file and 93 in the holdout file use it.

**Several values in one cell** use a semicolon, which is the template's own
separator: `GLO18; CON3; FRA33`.

**`results_set`** holds every acceptable result value for a project in one
cell rather than `result1`, `result2`, `result3`. The order a document lists
its results in is arbitrary, so scoring them position by position marks correct
answers wrong. A value counts as right if it matches anything in the set.

**Prose fields are not in the answer files.** Things like `location_notes` and
`rationale_project` cannot be scored by string comparison, so they are checked
a different way, by matching each quoted sentence back to the page it cites.

**`project_code` is the join key.** P002, P003 and P004 share one source PDF, a
294-page evaluation covering three programmes, and are separated by the `focus`
column in `documents.csv`.

## Where location codes come from

A code like `P001.12` is **not generated by a rule you can reimplement**. The
accepted codes live in a registry, exported to `../template/location_codes.csv`
(677 rows). The number after the dot is a sequence number, assigned in the
order places were first recorded for that project. It carries no meaning;
`P001.12` is simply the twelfth place recorded for P001, which happens to be
Burundi. `.0` is reserved for "unspecified".

A place not already in the registry gets a proposed code, which a person
accepts or rejects before it becomes permanent.

## How the answers were made

A manual extraction of the ten projects, done from the source documents by the
template owner. It was then audited field by field against those same
documents, and corrections were applied under rules agreed with her. Roughly
240 fields were checked; about 77% were confirmed with page evidence.

**Known residual disagreements are recorded**, not hidden. Where the manual
answer and a later reading disagreed, the ruling and the reason are in
`../catalogues/gold_v1_adjudication.csv` (21 rulings). In 12 of those cases
neither answer was judged correct. Treat the reference as a careful human
record with known errors, not as ground truth.

## Scoring

```
Rscript R/08_quality/score_pilot.R <your_output.csv> catalogues/gold_v1_general.csv
```

It reports per-field agreement across 18 fields plus the result set, metric and
unit, with verdicts `match`, `partial`, `candidate`, `mismatch`, `both_empty`.
The headline percentage counts `match` and `both_empty` as agreement.

Some comparisons are deliberately not literal: actor codes are expanded before
comparison, so `GLO62` matches "Adaptation Fund"; report ids ignore zero
padding, so `ICR00004849` matches `ICR4849`; and numbers of a thousand or more
are rounded so a decimal never decides a verdict.

`R/08_quality/score_locations.R` does the location sheet, which is scored as a
set per project rather than row by row.
